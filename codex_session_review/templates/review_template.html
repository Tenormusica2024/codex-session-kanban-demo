CodexセッションKanban

直近の “短くない” Codex session を board 化。drag / status select は human override 扱いにして、 後段 AI sync はそれを戻さない前提で使う。

形式 静的HTML優先 保存先 localStorage 運用 AI優先 / 手動修正可 用途 配布用・fixture built unknown

このKanbanの使い方

このボードは通常の開発Kanbanより、AI秘書のセッション整理に寄せています。 左から「候補確認 → 待ち/保留 → 作業ループ → 障害 → 完了履歴」の順です。

要確認
人間確認待ち。実働テスト後にUIや成果物を見て判断する段階もここ。
保留
やる予定だが今は待ち・保留。タイミング待ち、情報待ち、後回し。
進行中
AI/人間どちらかが作業ループ中。AI駆動開発では、AIがレビューしながら直す段階もここ。
停止中
認証、外部環境、権限、ユーザー操作など明確な障害で進めない。
完了
完了履歴。通常は折りたたみ、必要な時だけ見る。

判断目安: レビュー中 = 進行中 / レビュー待ち = 要確認。

ショートカット: / で検索、? で使い方、Esc で閉じる。j/k で選択移動、Alt+↑/↓ で同列順位変更、1-6 で状態変更、c でsession IDコピー。入力欄フォーカス中は無効。

候補一覧は staging。`推奨列へ追加` か `要確認へ仮追加して選択` で初めてボードに固定され、固定済み候補は候補一覧から消えます。

URLの使い分け

個人用: 実セッション入りのため、このpublic demoには含めない。

配布用: sample fixtureだけで生成。公開前に -Distribution guard を通し、個人セッション・ローカルパス・bypass token を混ぜない。

配布版は sample fixture だけから GitHub Actions で生成します。外部 LLM API や実セッションは使いません。
